## 2024-03-22 - [Performance Optimization] Direct String Sorting & Object Allocation Avoidance
**Learning:** Parsing `new Date()` within a map-sort-map (Schwartzian transform) is slower and allocates more memory than a direct string comparison `(a < b ? -1 : a > b ? 1 : 0)` when the strings are strictly ISO 8601 formatted dates (like `startTime` or `utcDate`). Additionally, using `Object.values(obj)[0]` within frequently called helper functions like localization maps creates unnecessary array allocations that significantly drag down performance and trigger frequent garbage collections.
**Action:** Always prefer direct string comparison for sorting ISO 8601 timestamp strings. Opt for explicitly accessing known keys (`obj.en` or `obj.pl`) or using a `for...in` loop with an early return rather than methods that iterate and allocate arrays like `Object.values` or `Object.entries` on hot code paths.
